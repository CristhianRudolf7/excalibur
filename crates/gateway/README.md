# Authenticated client gateway

The Axum gateway serves JSON-RPC 2.0 on `/rpc` over WebSocket and HTTP POST, and bounded binary uploads/downloads on `/blobs`. Every request, including loopback traffic, requires `Authorization: Bearer …`. URL query parameters are rejected. Browser origins must appear in the host's exact allowlist; nonbrowser clients may omit `Origin`. Hosts provision a random token of at least 32 characters and terminate TLS before exposing the listener beyond a trusted local connection. The policy stores a SHA-256 digest and compares it using `subtle`; it never formats tokens. Denial counters record fixed categories and hourly buckets without headers, URLs or message bodies.

`SharedBackend` connects the existing master, orchestrator, task and security services. Its implemented methods are `conversation.send`, `conversation.list`, `conversation.history`, `conversation.subscribe`, `conversation.scope`, `conversation.stop`, `events.replay`, `run.list`, `run.status`, `run.spawn`, `run.pause`, `run.resume`, `run.interrupt`, `run.cancel`, `run.redirect`, `project.list`, `project.get`, `project.register`, `project.resolve`, `files.list`, `task.batch`, `task.get`, `conversation.activity`, `notification.list`, `notification.ack`, `notification.policy`, `metrics.query`, `config.get`, `config.read`, `conversation.retry_context`, `approval.list`, `question.list`, `question.answer`, and `approval.respond`. `task.batch` requires `with_task_actions`: it uses the same task mutation and durable correction propagation as the master; without that binding the write is unavailable. `daemon.stop` is available when the host binds its shutdown notification. An approval response releases only its matching approval wait or the exact system pause `approval required`. Approval permits the pending effect once; denial blocks it before another model request. A newer user pause wins through a revision-checked transition, and user-paused and terminal runs retain their state. Replaying the same authenticated response can finish a pending wake without repeating the grant. Methods for unbuilt capabilities return JSON-RPC `-32601`; no memory, skill, agenda, deployment or administrative configuration operation is implied.

`run.spawn` requires an existing origin conversation owned by the principal before persisting a delegation intent. Hosts call `Gateway::close_connections` before teardown: it rejects new work and closes WebSocket subscriptions, including idle subscribers. It also ends incomplete POST-body reads before backend admission; admitted backend actions retain their own completion contract.

`approval.list` returns this principal’s durable pending, unexpired requests without changing run state or granting authority. It accepts `limit` (1–100, default 20), optional `target` (agent or run), and the `after` cursor returned in `next`. Entries include approval/run/project identifiers, the action hash, deadlines, proposed scope, current run state and the approval request redacted through the live secret registry. The request retains its action, reason, risk and reversibility for a decision using `approval.respond`; listing preserves every pause; answering releases only the matching system approval pause and preserves user pauses.

`metrics.query` requires a `target` and the host’s `with_telemetry` binding; it returns real metrics for that execution. `config.get` and `config.read` return only the read-only snapshot supplied through `with_configuration`, without reading private files or modifying settings. These methods return `-32601` without their respective host binding. `conversation.retry_context` asks the master to explicitly retry context-budget-blocked messages in the active scope of an authorized conversation; it grants no permissions and deletes no messages.

Messages use the master's durable `(client_id, client_msg_id)` receipt. Reusing a receipt key with different content is rejected. A WebSocket `conversation.subscribe` request accepts `cursor` and an optional `conversation`; subsequent `event` notifications replay durable events in ascending cursor order and continue polling. The cursor is global for the authenticated principal. Clients retain their last processed cursor and resend unacknowledged messages after reconnecting. HTTP clients use `events.replay`. A conversation-specific subscription records presence and disconnects; multiple connections to that conversation share a count. `conversation.activity` supports explicit activity heartbeats, and `notification.ack` marks a notice read across channels. JSON-RPC batches are limited to 64 requests and preserve order; notifications execute without replies. WebSocket text messages are limited to 1 MiB.

`with_project_roots` is a trusted host ceiling: callers cannot expand it through project registration or file listing. Client scopes are `general` or an authorized registered project. `files.list` takes a project ID, root index, relative directory, optional filename cursor, limit (1–500), and `agent_only`. It lists a single directory, collapses subdirectories, applies inherited `.gitignore` and `.git/info/exclude` rules, omits credential/metadata paths, and filters agent changes against `file_versions`. Directory access uses capability-relative handles and refuses paths outside the host ceiling. Directories above 10,000 entries require a narrower selection. Listings do not read file contents.

`DaemonHost` additionally binds `with_project_registration_roots` to the exact roots provisioned at startup. Under that binding, `project.register` may update names, aliases, descriptions, settings and status, or register a new ID on an already provisioned root. It rejects new or nested roots and root remapping of an existing ID before persistence. A new ID is metadata only: selecting or writing its scope also requires membership in the master’s startup token. Adding roots, remapping them or enabling scopes requires explicit host reprovisioning and restart; permissions, exclusions and runtimes are not hot-updated. Without this optional binding, `SharedBackend` retains its generic root-ceiling contract and the embedding host must provide its execution boundaries.

Blob download requires a registered `gateway_upload` reference in this principal's database; knowledge of a private tool-output hash is insufficient. Uploads publish through the existing atomic, verified blob store and retain their reference. The host sets the byte limit, up to 64 MiB. Downloads are verified, `application/octet-stream`, attachment-only and `no-store`. Transport errors return fixed messages without underlying SQLite, filesystem, provider or credential details.

Run `cargo test -p excalibur-gateway` for real local HTTP/WebSocket authentication, protocol, blob authorization, cursor reconnection, durable intake/reopen, and confined project listing tests. These tests use synthetic models and data. They do not contact external services.
