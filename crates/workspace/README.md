# Workspaces and editing concurrency

The reusable `excalibur-workspace` library supplies durable file leases, isolated Git task worktrees, an integration queue, local edit-history plans and private shadow trees. The host retains filesystem capabilities, approvals, test execution and engine lifecycle responsibilities. It must supply a protected data directory and exclude that directory from project observations.

`Workspace::open(database, project_root, data_directory, redactor)` uses an additive checksummed schema. History/shadow/leases permit an explicitly supplied data directory inside the project; creation of Git worktrees requires it outside the project. Directory discovery never relies on the process working directory.

`leases().acquire_many(run, paths, activity)` canonicalizes and sorts paths and waits for at most 30 seconds. `Busy` includes the holder, current activity, path and expiration. Leases last 600 seconds, remain beyond individual tool calls, and use both SQLite and stable sidecar OS file locks. Cooperating daemons must use the same lock directory, including when they have separate databases. The in-process map is shared by database/project/lock-directory identity; the sidecar namespace still coordinates independent databases. An effect guard keeps the OS lock alive through a concurrent state release. `heartbeat` renews active runs and enables a 60-second renewal task. Running, verification, recovery and tool/child waits renew; pause, block, completion and human/approval waits release. The host must report state transitions. Production renewal reads the authoritative run journal and checks it again inside the writer, so a stale running notification cannot revive a paused or terminal owner. The timer retains only weak runtime references while sleeping. `*_at` methods use explicit synthetic time and avoid automatic renewal for deterministic tests. LocalTools shares one 30-second admission deadline across in-process resource locks and durable leases; a timeout includes the current holder/activity. Final database ownership explicitly unlocks its advisory database/blob locks after writer shutdown, so an inherited descriptor waiting for exec cannot retain ownership after the final Rust owner drops. Advisory locks do not prevent user edits; the existing read fingerprints remain necessary.

`history().version` and `file_history` read foundational `file_versions`. Additive `file_version_metadata` records pre/post entry kind and executable class alongside the original content blobs. `plan_revert_entry(edit, guarded_current_entry)` preserves regular files, literal symbolic-link targets and executable state; legacy records remain readable and do not invent missing metadata. `plan_revert(edit, guarded_current_content)` uses a pure Rust three-way merge: the edit's postimage is the ancestor, current contents belong to the user, and its preimage is the desired inverse. Conflicts return hashes and bounded conflict text without applying anything. The host must authorize the path, supply content through its capability-aware reader, then publish blobs and revalidate the returned fingerprint under the lease in its durable editing pipeline.

`shadow().snapshot_entries` accepts a complete map of authorized `SnapshotEntry {kind, content, executable}` values from that same host reader; the content wrapper `snapshot_files` remains available. Git trees preserve modes 100644/100755/120000 and literal link targets, including dangling links without reading their destinations. It never scans the project itself, follows private hardlinks, or reads protected files independently. It writes content objects and unreferenced trees to a private bare Git repository using a fresh private index. It never modifies the user's Git index or commits. Snapshots are keyed by run/step/phase; retries return the durable receipt. `diff`, `changed_files`, `list_snapshots`, `plan_restore`, `plan_restore_selected` and `plan_between` support inspection and conservative undo. Restore plans also require guarded current content; they merge later user changes and leave conflicting paths untouched. Typed restore plans carry expected kind and executable state as well as the content fingerprint. A changed type or mode conflicts even if bytes match. Link creation/restoration must remain inside the authorized root; unsafe destinations return a conflict instead of following them. LocalTools stages a temporary entry, rechecks current content and metadata, atomically replaces the leaf, fsyncs it and its parent, then records history. Recovery recognizes both pre/post metadata and does not duplicate versions. Selected restoration never includes unselected entries. Snapshot contents are bounded to 64 MiB per file and 256 MiB per snapshot. Known secrets are rejected before object publication or history-plan output.

`git().create(task, owner)` creates an integration branch and child branch/worktree under the data directory. A project without Git or with submodules uses `Shared` mode. Creation intent precedes Git effects, allowing retry after interrupted setup. `checkpoint_entries` requires an explicit host `GitIdentity`, an authorized entry/deletion map and a `CheckpointEntriesGuard` that rechecks content, kind and executable state. The content-only `checkpoint_files` wrapper preserves modes from HEAD. A private index starts at HEAD and stages only listed entries; unlisted tracked/staged files remain intact. It rechecks before the task-ref compare-and-set and updates only selected entries in the child index. There is no unrestricted add-all checkpoint API. `enqueue` freezes the child checkpoint and intent; `process_next` serializes queue operations, rebases only owned child branches, reports conflicts with both diffs, calls the host's `IntegrationChecks`, and fast-forwards only the integration branch after passing checks. Empty test evidence requires an explicit host reason that tests are inapplicable. Failed or interrupted tests return the branch without advancement; interrupted advancement is reconciled conservatively. External branch/working-tree changes cause rejection. `retry` continues a host-resolved rebase or explicitly retries returned work. `remove` refuses dirty worktrees and retains branch history. No API merges into the user's branch, pushes, or rewrites remote history. `assign_files` atomically persists each owner’s canonical assignment and binds its parent per project/task. It retains other owners and returns every overlap. `overlaps` reports intersecting canonical file assignments; code-graph expansion belongs to the host's code-intelligence adapter.

Git subprocesses clear inherited environment values, disable credential helpers, hooks, filesystem monitors, signing, automatic stashing, automatic updates to unrelated refs and lazy network fetching. The selected working tree is explicit. Local configuration is inspected by key name without expanding includes. Projects with config includes or custom shell filter/diff/merge drivers are rejected before these operations; support requires a separately confined host adapter, and is not claimed here. Test callbacks are host implementations, not unrestricted model shell commands.

Backend checks: `cargo test -p excalibur-workspace --test concurrency -- --nocapture` and `cargo clippy -p excalibur-workspace --all-targets -- -D warnings`. Fixtures exercise synthetic 20-minute heartbeat timelines, bounded waiting and state release, real independent daemon locks, three Git children with a conflict, failed tests, SIGKILL during queue testing, private-index isolation, hostile Git configuration and three-way recovery, persistent assignment isolation, typed chmod/link restoration and checkpoint metadata races. `cargo test -p excalibur-tools --lib entries::tests` covers real tool effects, metadata conflicts, interrupted reconciliation and lifecycle release; `cargo test -p excalibur-store --test fork_ownership` causally holds a child before exec to verify ownership release. Tests use temporary local repositories and synthetic data, never real credentials, remotes or inference services. These executions establish Linux behavior; compilation or runtime on other systems is not asserted.
