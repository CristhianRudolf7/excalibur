# Conversational master and durable intake

`excalibur-master` is shared Rust logic. The host supplies a principal database, model gateways, the live redactor and approved `FastActions`; it chooses the Tokio runtime. `Master::open` initializes storage without dispatching pending work. Bind host adapters before calling `retry_pending`.

`receive(Incoming)` persists the normalized message, its deterministic preanalysis and receipt with interactive storage priority before invoking a model or control action. `(client_id, client_msg_id)` is idempotent; reusing it with a different payload is rejected. Inbox capacity and payload sizes are bounded. `events(after, limit)` supplies durable global cursors for the principal; `history`, `conversations` and `conversation_scope` supply bounded reads. Read paths redact against the current secret registry.

Each admitted conversation has an independent Tokio task. `max_active_turns` defaults to sixteen active conversations; overflow remains in the durable inbox without loading histories or creating more tasks. Its model/tool transcript, source-message IDs and step count survive reopening. A turn permits at most eight model steps and only the approved fast-tool allowlist. Unknown tools and invalid schemas do not execute. File, terminal, browsing and long research tools belong to delegated executions. `FastActions::invoke_scoped` receives the scope captured from the original durable message, so changing the conversation selector cannot retarget an already admitted action.


Master context uses the shared `excalibur-context` compiler: L0 holds the rules and sorted fast-tool definitions; L1, configured identity; L2, the captured scope and configured conventions; L3, the first literal original message and its ID; L4, the confirmed recent view and turn activity; L5, current time, budget and refreshed brief jobs. Additional pending messages retain their complete text in L4. Tool results receive the compiler's untrusted provenance annotation.

`prompt_token_budget` defaults to 32,768 local input tokens, including a 10% margin, and `context_byte_budget` caps the serialized request at 256 KiB. The counter follows model metadata or a host-supplied `token_counter`; models without a known tokenizer retain a deterministic local estimate, not a claim of provider token accounting. Reads inspect sizes first: an oversized literal queue blocks before loading its full contents, and confirmed history defaults to a scoped tail of at most 64 messages and half the byte limit. Older sources remain complete in SQLite and the view identifies their omission; no summary is invented.

An exceeded budget emits `context_blocked` without calling the provider or deleting originals or receipts. Later messages cannot skip that blocked source. `retry_context` permits an explicit host retry after adjusting policy; `/stop` stops the pending turn. Compilation, hashing and counting run in the blocking pool selected with `set_context_runtime`; the standalone library uses its current runtime's blocking pool. Cache identity derives from principal, role and scope; changing jobs, time or activity does not alter the stable L0–L2 prefix. This establishes prefix eligibility, not a real provider cache hit.

New text received within two seconds of an unshown generation cancels that generation and rebuilds from durable pending messages. Later text enters at the next model boundary. `/stop` cancels only that conversation's master turn; explicit control commands dispatch independently of an outstanding model call. Host control adapters serialize the target execution's control operations. `stop_turn` guards final response persistence against a stopped inbox.

The principal gateway may have a fallback. An unavailable model emits a deterministic event and retains the inbox. Maintenance may call `retry_pending`; failed attempts use a bounded exponential retry window until a queued probe succeeds. `model_available` is an explicit host health/configuration signal that resets the circuit. Model calls and host actions have separate bounded deadlines. Shutdown cancels model waits and waits for bounded fast-action completion.

Fast effects have durable intent/result receipts keyed by their operation. Confirmed results are replayed. An interrupted intent is returned as uncertain and is not blindly executed again. The full conversation transcript is restored around those receipts. Hosts must preserve the operation key for their own idempotent mutations; uncertain effects require inspecting the host's durable operation before resolution.

`Lexicon` uses Aho-Corasick and preserves all ambiguous candidates. Preanalysis includes slash commands, explicit IDs, paths, HTTP(S) URLs and supported relative weekday/tomorrow clock expressions in the user's timezone. Ambiguous/nonexistent daylight-saving wall times remain unresolved. Optional `IntakeDecider` classification is bounded to 500 ms. Only validated high-confidence status/control decisions targeting an actually mentioned candidate take the fast path. Without a decider, natural language goes through the master's existing call; no extra conversational inference is inserted.

`MasterFastTools` optionally composes a host-secured deferred runtime. Only `search_tools` and `call_tool` enter the master definitions; the delegate's eager file/terminal core is never exposed. `CallerRole::Master` filters non-fast tools at discovery and execution. Scope checks and a ten-second maximum fast-tool contract are enforced again when calling a catalog entry. The host must register the supplied run and enforce capabilities in the underlying runtime.

`Incoming.reply_to` can identify a pending question in the same conversation. The receipt commits first; subsequent routing retains the original reference, answers through the same compare-and-set as `question.answer`, consumes the incoming inbox entry and creates exactly one answer linked to its literal source ID. Both records retain the question's scope even after the selector changes. Without an explicit reference, automatic routing requires one mandatory question in the receipt's scope, no earlier unfinished work and no attachments. Unknown or foreign-conversation references and ambiguous answers produce deterministic selection/no-match events without a model guessing. Ordinary replies to existing messages in the same conversation continue through conversational intake. The durable routing phase is recovered before content reaches a model; replaying the receipt never duplicates the answer. `/proyecto` normalizes to the same action as `/project`.

Questions retain mandatory/nonblocking status and their literal text. At most three questions may be asked per source message. Mandatory questions never apply defaults and emit daily reminders. Nonblocking defaults may apply after fifteen minutes when the conversational actor is idle; they are recorded as assumptions. Explicit answers are compare-and-set, idempotent and enter a scoped durable inbox. Notification publication is idempotent by ID and payload; normal notices use a deterministic message, while urgent notices also enter the next safe master boundary. The daemon's notification policy decides routing and quiet hours; the master durably groups normal deliveries. A notice may carry its original `scope` so the active selector does not move its contents into another project's model context.

Run:

```sh
cargo test -p excalibur-master
cargo clippy -p excalibur-master --all-targets -- -D warnings
```

The fixtures use deterministic local gateways and real SQLite. Availability tests cover blocked-provider control, concurrent conversations, both steering windows, fallback, scoped history, bounded steps and receipt replay. The Unix subprocess test kills a process with SIGKILL after a synthetic durable effect and before its receipt; reopening returns uncertainty without repeating that effect. Linux was exercised locally; this is not a claim of verified behavior on untested platforms or real model-service latency.

Each provider attempt has a durable `model_attempt_started` ID and a matching `model_usage` or typed `model_failure` event when observed. Events distinguish primary and fallback adapters, actual provider metadata, price availability, cache fields and usage. A cancelled pending attempt retains null unknown usage, provider-call count and cost; it is not counted as a free or zero-token call.

Durable human provenance is exposed by `client_sources` and the additive SQLite view `master_user_sources`: canonical message ID, original human message ID, literal human text, captured scope and conversation. The view also exposes the durable receipt cursor. Clarification aliases contain only the human answer. Generated question prefixes, notices and timeout assumptions never become authorization sources. `invoke_source_scoped` supplies the canonical source to host authorization; `ask_for_source` limits clarification to three questions for that source, independent of other requests. Trusted host calls to `ask_scoped` form independent batches.

Maintenance calls `retry_pending` to probe queued work after `recovery_initial_delay` (five seconds), exponentially bounded by `recovery_max_delay` (sixty seconds), without a permanent attempt limit. The circuit admits one queued conversation while unavailable and records one durable outage notice until a successful attempt. Each primary/fallback attempt has its own `model_timeout`; failed availability probes preserve the conversational step budget. No separate model health request is issued. Explicit slash controls bypass conversational queue capacity. Status and control replies use a bounded field allowlist rather than exposing host operation records. Recognized compound controls execute their control once and atomically enqueue the literal remainder for the conversational path; human-source provenance retains the complete original. Unrecognized compound forms remain complete in the conversational path.

`publish_notice` stores normal deliveries in a durable five-second bucket; hosts call `flush_notices(now)` to emit a grouped template (up to 32 members per message) without inference. Informational `publish_link` never starts a model turn. Urgent reports from a different scope remain visible as scoped reports/events without creating an unreachable inbox item or importing another project's instructions. The original notice IDs remain idempotent through restart and grouped publication.
