# Code graph and local language servers

This crate implements the shared backend for architecture sections 10.10 and 13.8. It exposes graph data and local language features; it does not apply file edits, execute server-proposed commands, render a graph or call inference services.

## Incremental project graph

Open the dedicated `codegraph.db` through `CodeGraph::open(database, project_id)`. Its checksummed additive schema reuses storage's `files`, `nodes`, `edges` and FTS tables. A database is bound to one project; existing file identities are preserved and newly generated identities include the project namespace. Database writes go through the shared asynchronous storage writer and commit each file's replacement graph atomically.

`index_path_content(relative_path, content)` detects the grammar through `Language::from_path`; `index_file` accepts an explicit language. The host supplies authorized UTF-8 content and relative paths. The source hash is computed from the exact input. Matching hash, language and index grammar generation skip parsing and writes, including after restart. Changed in-memory trees use a real Tree-sitter `InputEdit` followed by parsing with the edited previous tree. A changed file without a cached tree uses a cold parse. `IndexReport.mode` distinguishes these cases.

Bundled grammars cover Rust, Python, JavaScript/JSX, TypeScript, TSX, JSON and Markdown. Other file types return `UnsupportedLanguage`. Sources larger than eight MiB and syntax nesting deeper than 512 are rejected explicitly. Source text remains in the process's parser cache rather than being duplicated into plaintext SQLite content. Names and outgoing graph metadata can use the host's shared live `Redactor`; protected names are omitted and counted.

Nodes include files, modules, functions, types, methods, tests, documents and Markdown headings. Edges include definitions, imports, calls, references, test-to-code relationships and document citations. Tree-sitter gives syntactic relationships. A unique name match is labeled `syntactic_name`; ambiguous or unavailable targets remain explicitly `unresolved`. These edges are conservative candidates, not a claim of compiler-level type resolution. Syntax errors include missing anonymous punctuation and byte plus UTF-16 ranges. A syntax error can leave a useful partial syntax graph.

`query(GraphQuery)` supports symbols, callers, dependencies, files and explicit requirement implementations, with bounded result pages. `impacted_tests` traverses reverse relationships and returns a conservative test set; it does not run or invent tests. `link_requirement` records host-authorized mappings with provenance rather than guessing that a natural-language request has been implemented. `remove_file` removes dependent rows through foreign keys. `indexed_paths` supports deletion reconciliation after restart.

`enrich_lsp(manager, project, language, root, relative_path)` makes at most 32 definition/reference requests. It adds semantic edges only to already indexed targets whose synchronized document hashes and current confined file reads agree. Files outside the project, credential/harness metadata, unverifiable aliases, unavailable operations and targets without synchronized hash evidence are skipped or reported. Enrichment uses capability-based reads and descriptor authority checks. `enrich_edge` also exposes the hash-guarded primitive for other authorized adapters. It never substitutes a syntactic guess for an LSP result.

## Shared LSP lifecycle

`LspManager::new(Arc<dyn LspSpawner>)` requires a host-owned launcher. `register(project, language, ServerConfig)` stores configuration without starting a process. The first operation starts one shared process for that project/language pair. All callers share document versions and diagnostics. Configuration contains an absolute host executable, arguments, project root, explicit read roots, initialization options, environment and bounded request/frame limits; model arguments cannot select a server command.

The concrete `ReadOnlySpawner` uses the existing native `PreparedSandbox`, retains its descriptors and masks for the child's lifetime, clears the environment, passes declared values inside the confined namespace, and denies project writes and network access. It does not inherit credential variables. Before launch, inode inventories cover read and write roots: hardlink aliases to hidden files, protected metadata or unaccounted external origins are masked, including aliases in read-only roots. Ordinary links wholly inside authorized roots remain available; the stricter write boundary is checked separately. The child has a parent-death signal and kill-on-drop. This adapter and its real processes were checked on Linux x86-64. The Rust graph and protocol contracts are shared; other host adaptations can implement `LspSpawner`. No native-confinement verification is claimed for another environment.

Sessions shut down after ten minutes without operations; a maintenance pass checks idle time and the background reaper runs independently of tool calls. In-flight operations prevent idle shutdown. Explicit `reap_idle` permits deterministic host maintenance tests. Shutdown sends `shutdown`, then `exit`, waits and forces termination if required. A closed server restarts lazily under a bounded restart policy. Dropped/timed-out requests remove pending IDs and send best-effort `$/cancelRequest`; a server need not honor cancellation, so confinement remains in force until it stops.

`sync_document` sends `didOpen` or a versioned full-document replacement, using the server's full/incremental synchronization mode and UTF-16 positions. `request` supports definition, references, document symbols, workspace symbols, diagnostics and rename, with capability checks. `LspReply` includes document hashes/versions captured before the request. Rename rejects a concurrent change to any captured document and returns only a `WorkspaceEdit` proposal. The host must authorize and fingerprint every affected file before applying it through the ordinary durable edit pipeline. Unknown/unopened targets require a prior authorized read and synchronization. Server-initiated `workspace/applyEdit` is rejected; no command execution method is exposed.

Diagnostics support pull reports and versioned push publications. Snapshots contain current and published versions, freshness, diagnostics, newly observed errors and an explicit unavailable reason. Error comparison uses range, severity, code, source and message. Unversioned push reports are not declared fresh. Version freshness is not proof that all asynchronous server analysis has finished: a server can publish more than one report for a version. A later `Diagnostics` query retrieves the latest report; this is not a compilation/test success claim. Tree-sitter reports syntax errors independently. Bounded server notices and stderr are redacted in memory and available through `server_messages`, never written directly to terminal logs.

## Evidence

`cargo test -p excalibur-code-intelligence` uses synthetic local repositories, real SQLite and real confined stdio processes. Graph tests cover no-op hashes, true incremental edits, Unicode, multilingual symbols and citations, known impacted tests, concurrent indexers, anonymous missing punctuation, restart/deletion, legacy identities, project isolation and hash-guarded enrichment. Protocol fixtures cover all six operations, push/pull diagnostics, UTF-16 changes, stale rename rejection, cancellation, restart, frame bounds, unavailable capabilities, namespace separation and denied server writes/apply-edit requests.

A native test uses the installed official `rust-analyzer 1.99.1` and Rust sources against a synthetic Cargo project in ReadOnly confinement. It verifies definitions, references, symbols, rename proposals, actual new syntax diagnostics and real LSP-to-graph enrichment. Native diagnostics are awaited under a watchdog because publication is asynchronous. The test explicitly reports absence of the optional component on another host; fixtures still verify the real protocol and native boundary. It does not claim other servers or platforms were tested.

Relevant checks are `cargo fmt --check`, `cargo clippy -p excalibur-code-intelligence --all-targets -- -D warnings` and `cargo test -p excalibur-code-intelligence`. Installation performed here: `rustup component add rust-analyzer rust-src`. No credentials, paid services or model calls are needed.

Official contracts and pinned grammar sources: [Tree-sitter editing](https://tree-sitter.github.io/tree-sitter/using-parsers/3-advanced-parsing.html), [LSP 3.18](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.18/specification/), [rust-analyzer installation](https://rust-analyzer.github.io/book/installation.html), [rust-analyzer initialization options](https://rust-analyzer.github.io/book/contributing/lsp-extensions.html#configuration-in-initializationoptions), and [Tree-sitter Rust bindings 0.25.10](https://docs.rs/tree-sitter/0.25.10/tree_sitter/). Exact grammar versions are pinned in this crate's Cargo manifest and resolve to the maintainers' grammar packages; no grammar is downloaded at runtime.
