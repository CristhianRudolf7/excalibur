# Pinned telemetry reference validators

[Español](README.es.md)

`harbor/` contains the unmodified trajectory and AgentContext models from Harbor 0.25.0, commit `509b119db0d97b141dcd9c80f4f7ab861c47c2d6`, under the included Apache-2.0 LICENSE. `harbor/PIN.json` records each source SHA-256. The root `atif-v1.8.schema.json` was generated by `Trajectory.model_json_schema()` with Pydantic 2.12.3; the validator checks it against those exact sources before validating fixtures.

`genai/` retains the official Development conventions used by the local OTLP JSON exporter, commit `3fe84604a581b3d50dd5b4bd29383b462d2a5018` of `open-telemetry/semantic-conventions-genai`, with its Apache-2.0 LICENSE and source hashes. `validate.py` checks attributes/kinds and parses the generated `opentelemetry-proto==1.45.1` `ExportTraceServiceRequest`. OTLP requires hex IDs; the script converts them to base64 only for the generic protobuf JSON parser.

Install `requirements.txt` into a temporary Python environment and run `python reference/validate.py` from the crate, or pass artifact directories/files. Validation itself is offline. The default fixtures are synthetic outputs produced by the Rust integration tests, not benchmark results. Source repositories: [Harbor](https://github.com/harbor-framework/harbor/tree/509b119db0d97b141dcd9c80f4f7ab861c47c2d6), [GenAI conventions](https://github.com/open-telemetry/semantic-conventions-genai/tree/3fe84604a581b3d50dd5b4bd29383b462d2a5018), [official Python OpenTelemetry protobuf distribution](https://pypi.org/project/opentelemetry-proto/1.45.1/).

`check-platform-adapters.py` creates an isolated temporary Cargo manifest which imports the real `src/resources.rs` with minimal error-type scaffolding. It type-checks only that module for installed Windows/macOS Rust targets. It does not link/run a program or claim a complete crate/workspace cross build. Native Linux resource comparisons and synthetic cgroup tests are in `tests/resources.rs`.
