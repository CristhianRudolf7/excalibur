# Biblioteca de proveedores: cobertura actual

[English](provider-implementation.md)

`excalibur-providers` es una biblioteca Rust inicial de conexiones salientes, independiente de CLI y servidor HTTP. Es una implementación parcial, no la finalización del plan de proveedores. No se ha probado ninguna cuenta, disponibilidad de modelo, facturación ni operación real. Quien llama proporciona modelo, credenciales y mensajes; no hay almacén de credenciales, descubrimiento, normalización de herramientas, salida estructurada, reintentos automáticos, alternativas, cálculo de costo por tokens ni bucle de agente. Las respuestas de texto exponen consumo cuando el proveedor lo ofrece; solicitudes y respuestas pueden contener información privada y no deben registrarse. Los secretos se ocultan en `Debug` y se borran al liberar sus copias, aunque HTTP/TLS puede crear copias transitorias. Se exige HTTPS salvo loopback literal; las redirecciones están desactivadas. Una URL personalizada envía credenciales al servidor elegido, que debe ser confiable. Si una petición facturable agota el tiempo, su resultado es incierto; no reintentar a ciegas.

El método `chat` básico es solo texto: mensajes de sistema/usuario/asistente, modelo y límite opcional de tokens de salida. Aplican restricciones de proveedor y modelo. `native_chat` admite el cuerpo nativo de herramientas y devuelve la respuesta completa; `stream_native_chat` entrega eventos SSE sin ensamblar deltas para rutas compatibles, Anthropic, Cohere, Google y Vertex. El consumidor debe reconstruir llamadas y proporcionar los resultados con el formato del proveedor. La compatibilidad depende del modelo; los proveedores que no exponen el contrato correspondiente no usan esta interfaz. Anthropic requiere `max_tokens`. Google utiliza `generateContent` nativo. El método básico no conserva razonamiento ni herramientas; en la interfaz nativa el consumidor debe conservarlos íntegramente. El método común `generate_image` acepta solo modelo y descripción y devuelve datos sin normalizar. El inicio de video de xAI y la consulta de estado son operaciones separadas; quien llama gestiona espera, fallos, expiración y URL temporales. DigitalOcean crea un Droplet con región, tamaño e imagen elegidos; la biblioteca no verifica que el tamaño tenga GPU ni prepara cargas. Crear un Droplet o solicitar inferencia puede generar cargos. Los errores de estado omiten intencionadamente el cuerpo de respuesta.

Ejecutar `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings` y `cargo test --workspace`. Las pruebas usan servidores locales simulados y credenciales sintéticas; no demuestran que un proveedor acepte una solicitud. No hay pruebas de inferencia pagadas ni reales.
