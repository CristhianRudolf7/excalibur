# Caché de entrada por proveedor

`ProviderGateway` (también exportado como `OpenAiGateway`) aplica controles de caché en la frontera Rust compartida de modelos. `ModelRequest.cache` es opcional y se omite en solicitudes antiguas serializadas. `CacheIdentity::new` calcula un hash de principal, rol y ámbito delimitados por longitud; las claves del proveedor no contienen identidad literal. El host aporta los límites de capas y el hash del prefijo estable. Cambiar de modelo o configuración de rol produce una identidad distinta de pasarela. La reproducción restaura la política de contexto grabada mediante `context_policy_override`, los metadatos de caché exactos de cada paso mediante `request_cache_override` y el uso registrado para calibrar, sin generar tráfico nuevo. El motor valida la política antes de usarla.

| Adaptador | Contrato de solicitud | Contabilidad declarada |
|---|---|---|
| Anthropic Messages | Hasta cuatro marcas ordenadas `cache_control` en bloques de contenido, `ephemeral` con `5m` o `1h`. Sólo las capas iniciales L0–L3 forman el sistema estable; L4 y L5 conservan su posición incluso antes del primer turno de actividad. Las definiciones completas de herramientas permanecen cuando `tool_choice` pasa a `none`. | La entrada inclusiva suma tokens sin caché, leídos y creados. Conserva contadores separados de lectura, creación y creación de 5m/1h. |
| OpenAI Chat Completions | `prompt_cache_key` estable; catálogo completo ordenado y `tool_choice: auto/none`. No envía TTL de Anthropic ni opciones especulativas. Retención y mínimos dependen del contrato real del modelo/API. | La entrada incluye los tokens en caché; `cached_tokens` es un subconjunto. La escritura ausente queda desconocida. |
| Gemini generateContent | Caché implícita: conserva el prefijo común sin parámetros adicionales. Las instrucciones tardías conservan su orden mediante marcos explícitos de usuario porque esta API sólo admite roles de conversación user/model. | Entrada total y subconjunto en caché declarado; respuesta y pensamiento forman la salida. |
| Endpoints compatibles económicos/locales | Conserva prefijo y catálogo, sin inyectar controles de otros proveedores. El servidor debe admitir y activar la reutilización. | Los aciertos de DeepSeek son lecturas; los fallos son entrada sin caché, nunca escrituras. Reconoce contadores compatibles de Qwen. |

Las partes de respuesta de Gemini, incluidas las firmas de pensamiento e identidades nativas de llamadas, son datos opacos durables en `Message.provider_state`. La reproducción comprueba que texto visible y llamadas coinciden antes de devolver las partes originales. Conserva igualmente bloques de pensamiento y firmas de Anthropic. Estos adaptadores cubren texto y llamadas a funciones; no afirman admitir toda parte multimedia nativa. Los controles de muestreo/pensamiento específicos no soportados fallan explícitamente. `GatewayConfig.native_system_updates` permite que el host declare el soporte nativo de Anthropic; sin override se usa una lista conservadora de modelos documentados. En modelos antiguos/desconocidos o posiciones inválidas, las actualizaciones se representan como marcos de usuario conservando el texto literal y la posición. Los datos opacos nunca se añaden como texto de instrucciones al protocolo compatible.

`complete_fanout` usa `complete_cache_warm_observed` para iniciar una vez al primer hermano real de Anthropic, espera su primer delta útil y admite después a los demás dentro del límite de concurrencia. Si el primero falla antes, los demás quedan sin enviar. Descartar el futuro cancela las solicitudes locales activas. Una salida vacía correcta libera a los demás al terminar y declara esa diferencia. Los métodos públicos ordinarios de streaming de los workers siguen entregando únicamente la respuesta completa; el flujo interno de calentamiento admite deltas sin cambiar ese contrato. Este auxiliar no crea ni gestiona tareas de subagentes.

`CacheObservation` compara elegibilidad del prefijo con contadores devueltos. Igualdad de hashes no acredita un acierto; los contadores ausentes siguen como `None`. La contabilidad rechaza subconjuntos inconsistentes. Las pruebas usan HTTP/SSE locales, incluidos fallos de caché con prefijo idéntico, liberación incremental, errores y cancelación. Acreditan el adaptador, no tasas de acierto ni ahorros de producción.

Verificación: `cargo test -p excalibur-models --test cache` y `cargo test -p excalibur-models -p excalibur-providers`.

Los contadores o aciertos no declarados por el servidor permanecen desconocidos.

El perfil opcional vigente para inferencia real es `gpt-6-luna` con `GatewayConfig.reasoning_effort = Some("low".into())`. Las regresiones sintéticas siguen siendo offline. La comprobación de inferencia por Chat Completions omite herramientas de función: [el contrato de Luna](https://developers.openai.com/api/docs/models/gpt-6-luna) restringe sus llamadas a funciones por Chat Completions al esfuerzo `none`; las llamadas a funciones con esfuerzo low requieren Responses, que esta pasarela de modelos no declara implementada. Embeddings (`text-embedding-3-small`) y Decisions API son capacidades separadas y no se invocan al preparar contexto/caché. El host aporta las credenciales de prueba de forma privada; nunca se serializan en contexto o réplica.
