# Durable telemetry and trial artifacts

[Español](telemetry.es.md)

`excalibur-telemetry` is a reusable Rust library. It consumes confirmed journal events, stores a redacted append-only projection in `telemetry.db`, exposes a durable global cursor, and publishes trial artifacts after every recorded event. It does not call models, calculate prices independently of the model gateway, execute benchmark verifiers, or contact an OpenTelemetry collector.

## Host integration

Create `TelemetryConfig::new(directory, RunMetadata, Redactor)` with the same live redaction registry used by the executor. The host supplies the effective configuration, task/trial/benchmark identity, Excalibur commit, model/provider/role, reasoning effort, supported seed/temperature, profile version, tool/skill catalog hashes and environment description. Missing metadata remains `null`; the library does not invent a commit, benchmark result, or supported model parameter. `configuration_hash` is SHA-256 of the serialized **redacted** effective configuration. Run metadata becomes immutable when registered.

- `Telemetry::open(config).await` opens the dedicated database through the shared storage writer and read pool, and verifies the extension schema checksum.
- `record_event(run, &journal_event).await` is idempotent by `(run, journal, sequence)` and rejects changed content at the same identity. It returns only after durable insertion and artifact publication. A failed export can be retried without duplicating accounting.
- `reconcile(&journal, run).await` backfills confirmed source events after interruption. Original events retain their timestamps; newly recovered events are marked `recovered`, and elapsed/waiting times that cannot be reconstructed remain unknown. The original source-payload digest makes retransmission stable when the live redaction registry changes.
- `events_after(cursor, limit).await` returns up to 1–4096 records in global cursor order. `subscribe(cursor)` returns a subscription whose `next().await` first drains persisted records and then waits for notification. Reconnection does not rely on a lossy in-memory queue. Shutdown wakes subscriptions with a storage error.
- `JsonlSink::new(writer)` or `JsonlSink::after(writer, cursor)` writes and flushes a complete newline-terminated event at a time. Duplicate cursors are skipped. An interrupted writer is poisoned; reconnect using its last confirmed `cursor()`. `decode_jsonl_prefix` recovers complete records and discards only an unfinished final line, rejecting malformed complete lines.
- `finalize(run, &serializable_snapshot).await` records the snapshot and publishes final metrics. A host may enrich the snapshot with `exit_code` and `failure_class`; these are not guessed from a missing exit status.
- `record_verifier(run, reward, output).await` is a **trusted host-adapter** entry point. It rejects non-finite rewards, redacts output, and records `VerifierResult` with `host_adapter` provenance. Reward/output are unknown until supplied; this method never reads or runs verifier files.

Events contain the original journal kind/key/sequence and payload, a stable typed category, cursor, timestamp, recovery flag, and typed `{path, diff}` edit records found in tool results. Categories cover lifecycle, model requests/dispatches/responses/failures, tools, approvals, directives, memory writes, compaction, loops, masking, retries, errors, edits, gates and checkpoints. This vocabulary supports recording future producers; it does not implement memory, compaction, skills or subagents.

The engine host must feed confirmed journal events before allowing the next effect. The library's journal reconciliation addresses the gap between source confirmation and observer insertion; it does not replace the source journal. Metadata configuration and directory paths are trusted host inputs. Run IDs reject traversal segments and separators.

## Incremental files and recovery

`directory/runs/<run>/` contains `metadata.json`, `events.jsonl`, `journal.jsonl`, `resources.jsonl`, `metrics.json`, `trajectory.json`, `agent-context.json`, optional `otel.json`, and a SHA-256 `manifest.json` recording the last exported cursor. The first run is persisted as primary; `bind_primary_run(run).await` explicitly confirms that binding and rejects a different primary.

For the primary run, telemetry files are also published directly in `directory`. `trajectory.json` and `agent-context.json` go to `config.artifact_root`, or to `directory` if unset. Thus the installed host uses `directory=/logs/agent/excalibur` and `artifact_root=/logs/agent`. These aliases exist from the first event, not just at finalization.

Each JSON snapshot and JSONL export is written through an owner-only temporary file, synced, and atomically replaced; Linux also syncs the parent directory. New state directories use mode 0700 on Unix. Separate files are not one filesystem transaction: a kill may leave individually valid snapshots at different cursors. The manifest detects a mixed generation and replay/export repairs it from the database. A failure after database insertion leaves a recoverable pending export, not a missing source event. File snapshots are regenerated from the run's projection at each export; cumulative serialization/I/O grows with history. The streaming sink writes only new records.

Registered secrets and credential assignment patterns are redacted before persistence. Credential-shaped JSON fields such as `api_key`, `authorization`, `password`, `access_token` and `private_key` are masked as structured values so redaction preserves JSON syntax. Exports/read APIs apply the current live registry again. Register secrets before events are produced: later registration cannot retroactively erase an unknown value already committed to historical storage.

## Metrics and resource measurements

Metrics distinguish logical model calls from physical provider requests. The versioned `run_started.model_dispatch_protocol=1` contract separates a compiled `model_request` from the durable `model_dispatch` recorded immediately before gateway invocation. An unmatched dispatch increments `pending_model_calls` and logical/per-role/per-model counts; physical-request count stays an observed subtotal, its knowledge flag becomes false, and usage, cache, cost and duration are incomplete. Input/output token values remain known subtotals. A response or failure resolves the matching pending operation exactly once. A protocol-1 request stopped before dispatch consumes no model call. For legacy journals without the marker, an unmatched request cannot establish whether invocation happened: it is reported as unresolved pending usage instead of certain zero. Recovered dispatches never supply an original live timing interval. ATIF/AgentContext total tokens stay null while a call lacks usage, with known subtotals and pending counts in metadata. `provider_calls_known` is false when an adapter cannot observe physical requests; `usage_known` is false for estimated or provider-unconfirmed totals. Unknown cache reads/writes, reasoning usage and cost remain `null`. Costs and price-table version/hash come from observed model metrics. A schema retry contributes both attempts; deterministic replay records zero actual provider usage/cost and preserves historical usage separately as `recorded_*`. Per-model/role counts, per-tool counts, durations, gate attempts/pending criteria, final state, interventions, correction events, retries, subagent depth, compaction/masking/loop counters and errors are aggregated from actual events. No event from an unbuilt capability means a zero counter, not a claim that the capability exists.

Model duration prefers the gateway's monotonic measurement. Tool duration prefers the confirmed result's explicit duration, otherwise a live intent/result interval. This measures the tool invocation; a background terminal process may outlive its launch invocation. Model/tool time sums invocation durations; parallel tools can overlap, so their sum need not fit inside elapsed wall time. Waiting time covers live paused intervals. Backfilled wall-clock durations are not fabricated. Criteria are marked fulfilled when a completed snapshot confirms all mandatory criteria; partial per-criterion fulfillment remains unknown without explicit evidence. A missing failed-call usage report is recorded as an incomplete token subtotal, not as confirmed zero usage.

`start_sampler(run).await` records an initial sample, samples every second, and records a final sample on `ResourceSampler::stop().await`. Stop samplers before `Telemetry::shutdown`. The host can call `sample_resources` directly. Resource probing runs outside the database writer. Concurrent probes allocate their durable sequence inside the writer transaction.

| Platform adaptation | Actual measurements and limits |
|---|---|
| Linux | `/proc/<pid>/status` RSS and lifetime VmHWM; `/proc/<pid>/stat` CPU ticks converted to nanoseconds. An explicit host-supplied cgroup v2 directory supplies `memory.current`, `memory.peak`, `cpu.stat`, `pids.current`, `pids.peak`, and `memory.events` OOM/kill counts. The sampler does not create or move processes into cgroups. |
| Windows | `K32GetProcessMemoryInfo` working set/lifetime working-set peak and `GetProcessTimes`. An optional host-owned Job Object supplies `PeakProcessMemoryUsed`, `PeakJobMemoryUsed`, CPU accounting and active process count. Job memory peaks concern committed memory; these are not relabeled as RSS. OOM notifications and a kernel PID peak are unavailable through this read-only polling adapter. |
| macOS | `proc_pid_rusage(RUSAGE_INFO_V4)` resident size and lifetime maximum physical footprint. XNU CPU counters are Mach ticks and are converted through `mach_timebase_info`, using wide intermediate arithmetic. A per-task child-group peak, process count and OOM counter require a host grouping adapter and are explicitly unavailable here. |

`ResourceScope::{TaskChildren, TaskContainer, Shared}` states who owns the measured group; the library never infers exclusivity. Daemon baseline RSS, observed peak, delta above baseline, lifetime peak and CPU delta are separate. Group peak memory/PIDs and CPU/OOM deltas remain separate; the Windows per-process lifetime maximum is also retained. Shared daemon/container counters must not be presented as exclusive task memory. Missing files/access/counters remain unknown with `unavailable` evidence. A sampled RSS peak can miss a short spike; cgroup and Job Object lifetime peaks have different, explicit scopes.

## Pinned interoperability and verification

ATIF is fixed to **ATIF-v1.8**, Harbor **0.25.0**, commit [`509b119db0d97b141dcd9c80f4f7ab861c47c2d6`](https://github.com/harbor-framework/harbor/tree/509b119db0d97b141dcd9c80f4f7ab861c47c2d6/src/harbor/models/trajectories). The unmodified Apache-2.0 reference models, hashes, generated JSON Schema, requirements and offline validator are in [the reference directory](../../crates/telemetry/reference/README.md). Rust validates its emitted canonical JSON plus sequential steps, tool-observation references, source restrictions and content/reference consistency. Fixtures were also accepted by the official Python models, including partial trajectories and `AgentContext`. AgentContext's provider-unknown cache values are never replaced with invented zeros: incomplete per-model records are identified in metadata.

Optional local OTLP JSON uses `invoke_agent` INTERNAL, `execute_tool` INTERNAL and `chat` CLIENT spans with measured intervals, parent IDs and required operation attributes. The **Development** GenAI conventions are fixed to commit [`3fe84604a581b3d50dd5b4bd29383b462d2a5018`](https://github.com/open-telemetry/semantic-conventions-genai/tree/3fe84604a581b3d50dd5b4bd29383b462d2a5018). No unpublished schema URL is invented. Recovered absolute timing, deterministic replay and unknown model provider/timing produce explicit omission metadata rather than invented spans. The offline validator parses official `opentelemetry-proto==1.45.1` messages, adapting OTLP's specified hex IDs to generic protobuf's base64 bytes, and checks the pinned semantic attributes. No collector delivery was tested.

```sh
cargo fmt -p excalibur-telemetry --check
cargo clippy -p excalibur-telemetry --all-targets -- -D warnings
cargo test -p excalibur-telemetry
python3 -m venv /tmp/excalibur-telemetry-validator
/tmp/excalibur-telemetry-validator/bin/pip install -r crates/telemetry/reference/requirements.txt
/tmp/excalibur-telemetry-validator/bin/python crates/telemetry/reference/validate.py
```

Linux backend tests exercise cursor reconnection, all typed categories, diffs, duplicate/content-conflict handling, concurrent resource writers, run isolation, estimated/unknown/replayed usage, model failures, pending dispatch/restart/outcome reconciliation, protocol-1 preflight stops versus uncertain legacy requests, external verifier provenance, secret redaction, interrupted JSONL writes, and subscriber shutdown. A real SIGKILL test preserves valid partial artifacts and backfills a confirmed journal event exactly once. Resource tests compare a stopped 24 MiB child with independent procfs reads, verify synthetic cgroup units/peaks/CPU/OOM deltas and missing counters, and exercise the one-second sampler. Synthetic OOM counters are not a native OOM-kill experiment.

The actual resource module was separately type-checked for `x86_64-pc-windows-gnu` and `aarch64-apple-darwin`; these were not full-workspace cross builds or native Windows/macOS tests. Reproduce that limited check with `python3 crates/telemetry/reference/check-platform-adapters.py` after installing the Rust targets. Native Windows/macOS peak comparisons, host-owned child grouping there, a real benchmark/verifier run, and collector transport have no runtime verification in this environment.

Measurement sources: [Linux cgroup v2](https://docs.kernel.org/admin-guide/cgroup-v2.html), [Windows Job Object memory fields](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_extended_limit_information), [Apple resource ABI](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/bsd/sys/resource.h), [XNU Mach-tick accounting](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/osfmk/kern/task.c), and [OTLP JSON encoding](https://opentelemetry.io/docs/specs/otlp/#json-protobuf-encoding).
