# Scoped and current-run history

When memory is enabled and a worker has a durable memory binding, `history_search` retains the scoped memory adapter's schema and dispatcher. It searches messages and actions only inside the run's memory grant. `run_history_search` always addresses the bounded current-run journal and its archived observation references. Without a memory owner, `history_search` remains the existing journal alias.

A host-only `ToolRuntime::overrides_builtin` hook selects ownership before the first run context is compiled and when scheduling, preparing and executing a call. Decorators forward that hook rather than claiming ownership. Initial seed validation removes duplicate utility names; actual per-run context uses the bound owner's definition. Providing a definition never widens execution authority. `run_history_search` uses the same builtin audit gate and sanitization as its legacy alias.

Masked observations already identify `get_tool_output` with a durable blob hash; they do not direct journal recovery to scoped message history. That unambiguous retrieval hint remains intact.

`cargo test -p excalibur-daemon --test memory_history` exercises both actual dispatch paths with a mock model and local database. The engine utility tests compare the journal alias result with `history_search`. Final verification is pending at this source checkpoint; no full workspace or H11 completion is claimed.

After the master and worker shutdown joins, the daemon detaches the memory host from the orchestrator. This releases their authority/citation-tree reference cycle before storage shutdown. The integration fixture reopens the database after closing the memory-enabled host.

The native daemon delegation builder now sizes only L0 from its real composed core schemas, compiler estimate and selected counter. It conservatively includes duplicate schema variants that may be resolved after host binding and accounts for the host lane suffix. Its ceiling is the total run token budget and configured host input allowance; a provider input ceiling is applied only when the provider supplies a context policy. Unknown provider windows remain unknown. It builds fresh native contexts and never rewrites caller-supplied caps or `ContextInput::new` defaults. Domain schemas stay deferred.

The orchestrator owns that lane suffix. Each preparation removes a trailing marker byte-exactly, neutralizes any interior marker or trailing remnant that could form a second one, and appends exactly one marker for the delegation's priority. Re-preparing a stored delegation (for example, a child copied from its parent) therefore yields the same `{core}{marker}` text that native sizing counted; a priority change only swaps the one-digit lane. Previously each re-preparation added one newline to L0, which exceeded an exactly sized L0 budget. A marker at the very start of L0 that lacks only its first newline is also dropped, because the compiler's `[L0]\n` header would otherwise supply that newline and demote the request. `cargo test -p excalibur-orchestrator --test lane_marker` covers repeated re-preparation, priority swaps, foreign markers and leading markers checked against the compiled first system message.

Children created through the model-callable `subagent` tool size their L0 through the same native path (`Engine::native_context`): the parent's core text without its lane marker, the child's lane suffix and the child's own run budget, within the host and provider input limits. Previously they copied the parent's text but received the generic 4,096 default, so a memory-enabled native coordinator could not spawn a child (`invalid initial context`). A core that the child's run cannot afford is rejected at spawn. Independently, every spawn rejects a fixed or inherited L0 whose native core count (the same count `native_context` uses, including the lane marker) exceeds the run's `max_tokens`, before any durable spawn state is written; the per-layer cap itself is unchanged. `cargo test -p excalibur-daemon --test delegated_context` drives a memory-enabled native coordinator through a tool spawn to the child's first model request, and `cargo test -p excalibur-orchestrator --test delegated_context` covers sizing and both rejections.

A diagnostic coordinator measurement excluding skill tools found 27 tools, 14,105 bytes and 4,702 compiler-estimated L0 tokens, exceeding the generic 4,096 default. The corrected fixture principal is the actual default `local`. `cargo test -p excalibur-engine --test native_context_budget` checks sizing, unchanged other layers, explicit small-cap rejection and known/unknown provider limits. `cargo test -p excalibur-daemon --test native_context_budget` drives the production memory-enabled coordinator delegation to its first model request.
