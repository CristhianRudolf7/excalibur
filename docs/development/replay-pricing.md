# Deterministic replay and model accounting

The shared `excalibur-models` library implements recorded model replay and per-call accounting. It does not include prices, choose a model, discover credentials, or call a service during its tests.

`ReplayTape::from_journal` pairs confirmed `model_request` events with `model_response` or `model_failure`. It retains the original run seed and gateway identity. `save` creates a new private file without overwriting; `load` validates the format and a 64 MiB limit. Export only an already-redacted journal: a tape contains private task/context data. Request/response content is not included in tape Debug output or divergence diagnostics.

`ReplayGateway` serves the recorded outcome while the entire `ModelRequest` matches. It stops at the first mismatch or recording exhaustion. Diagnostics contain the call index, a structural pointer and SHA-256 hashes; arbitrary object keys are hashed, and differing values are never printed. No provider is called automatically. The engine uses `request_time_override` to restore the recorded L5 clock, without ignoring any request field. Other changes, including budgets, history, tools and instructions, remain observable divergences.

Recorded response usage is retained for the engine's deterministic logical budget and next compiled request. Actual replay metrics instead report zero provider calls, tokens and charge with explicit knowledge flags; historical usage and historical known cost are separate fields. Replay does not simulate tools or restore the workspace: reproducing file effects requires the same authorized starting state. Subagents, arbitrary memory retrieval and compaction are separate capabilities.

After a stop, `authorize_live` requires the exact divergence report, a priced gateway and an explicit approval identifier with positive call/token/cost limits. The first live request must match the approved divergence hash. Reservations are charged conservatively before dispatch; unknown call bounds deny live continuation. A returned count or charge exceeding its reservation stops further live calls and reports the overrun. These are application-side controls, not an independent guarantee about a vendor's tokenizer or invoice. The OpenAI-compatible preflight token bound is a documented local byte/framing estimate including its single validation retry; providers must report usage sufficient for the approved tariff. A cancelled in-flight replay/live request remains closed to automatic duplicate dispatch.

`complete_observed` and `complete_stream_observed` return `ObservedResponse` or `ModelCallError`; failures retain boxed `ModelCallMetrics`. Successful and failed HTTP attempts report duration, role/model/provider, configuration hash, attempt count and safe classified HTTP status. No response body, URL or credential is included in provider errors. Generic gateway defaults cannot observe physical provider calls and mark that counter unknown; the OpenAI-compatible adapter records its actual HTTP attempts. Missing cache/reasoning counters and cost stay `None`, rather than becoming measured zero. An unpriced gateway still supplies a token preflight estimate; its zero cost-bound placeholder is valid only with `cost_is_known == false` and is never reported as a zero invoice. Local token estimates are explicitly marked.

A host-supplied `PriceTable` identifies a version and exact provider/model entries. Rates are integer micro-USD per million tokens; the content hash includes version and rates. Input totals include cache reads and writes as subsets; reasoning is a subset of output. Separately priced subsets replace their ordinary rate and are counted once. Cache writes use their declared TTL, or the explicit `unspecified` tariff when the provider omits TTL; no TTL is guessed. An absent separate rate is an explicit host declaration of ordinary/included billing for that category. Missing counters required by a separate tariff make cost unknown, and a priced request fails closed. Overflow and inconsistent subsets are rejected. No real provider tariff is embedded or asserted current.

The OpenAI-compatible counter paths are verified against [official OpenAI streaming usage documentation](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events): `prompt_tokens`, `completion_tokens`, `prompt_tokens_details.cached_tokens`, `prompt_tokens_details.cache_write_tokens` and `completion_tokens_details.reasoning_tokens`. This does not assert native usage normalization for other wire protocols. Stream callbacks remain provisional host data and must pass the host redaction boundary before logging.

`GatewayConfig.seed` and `temperature` are optional host requests, omitted by default. A seed is a nonnegative signed-64-bit value; temperature must be finite within 0–2. Opting in sends the exact `seed` and `temperature` wire parameters and changes the gateway configuration hash. Defaults preserve the previous serialized configuration and identity. The [official Chat Completions reference](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) marks seed deprecated/beta and describes determinism as best effort, without a guarantee. Model support varies: mocks verify validation and transmission, not that a backend honors sampling or reproduces an answer. Recorded-request replay provides the separate exact-match behavior described above.

OpenAI HTTP failures additionally recognize a closed code allowlist: HTTP 429 spend/usage/credit limits become `quota`, HTTP 400 `context_length_exceeded` becomes `context_window_exceeded`, and HTTP 503 `server_is_overloaded` becomes `overloaded`. The legacy `insufficient_quota` code/type is accepted only with 429. These categories follow the [official HTTP error guide](https://developers.openai.com/api/docs/guides/error-codes) and the documented [context-window code](https://developers.openai.com/api/docs/guides/agents-api/errors). This is code recognition in the existing OpenAI-compatible adapter, not an Agents API implementation. Parsing retains at most 16 KiB of error-body bytes and ignores messages; diagnostics and metrics contain only the closed category and status. Unknown, malformed, oversized, conflicting-status and other-provider errors preserve the existing HTTP classification. There are no automatic quota retries. Metrics and replay preserve the distinct categories; a future external Harbor adapter must translate them to the installed reference's exception contract.

Verification uses synthetic rates and local mock HTTP/SSE responses:

```sh
cargo test -p excalibur-models
cargo test -p excalibur-providers
cargo clippy -p excalibur-models --all-targets -- -D warnings
```

The tests record and replay a real shared-engine run, verify zero new provider calls, changed request rejection, explicit approved live continuation, cache/reasoning accounting, integer overflow, SSE usage and real HTTP status classification. No paid inference, model, embedding service, GPU or real credential is used.
