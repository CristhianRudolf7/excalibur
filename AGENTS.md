# Agent instructions

- This repository contains provider, storage, minimum durable engine, durable task/planning and evidence, context/cache, project tools, code intelligence, editing isolation, security, vault, sandbox, telemetry and evaluation libraries, plus the noninteractive exec command. Do not describe planned application or interface capabilities as implemented.
- Keep directory names in English. Maintain English and Spanish documentation as paired files using the `.es.md` suffix, and update both when their shared content changes. This AGENTS.md is maintained in English only.
- Respect the scope of the task and preserve unrelated work. Do not invent credentials, contact information, licensing decisions or test results.
- Add implementation and verification commands here when the corresponding components exist.
- Write commit messages in natural, human language that clearly describes the change.
- Keep agent and provider logic in the shared core, not duplicated in the CLI or HTTP API. See [the architecture overview](docs/architecture/overview.md).
- Rust provider library checks: `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, and `cargo test --workspace`. Tests must use mocks and must not call paid APIs.

- Storage verification: `cargo test -p excalibur-store -- --nocapture` exercises concurrency, external locking, real WAL growth and deterministic subprocess interruption tests. See [Base and storage](docs/development/storage.md).

- Durable engine verification: `cargo test -p excalibur-engine --test crash -- --nocapture` covers real process interruption and effect reconciliation; `cargo test -p excalibur-engine --test end_to_end -- --nocapture` runs the shared engine through a mock provider and real local tools. See [Minimum durable engine](docs/development/durable-engine.md).

- Durable control and batch verification: `cargo test -p excalibur-engine --test control_races --test batch_preparation --test batch_crash`, `cargo test -p excalibur-journal --test state_transitions` and `cargo test -p excalibur-tools --test execution_conflicts` cover control races, sequential real file edits, unadmitted batches after SIGKILL, atomic state guards and durable conflict escalation.

- Security verification: build the internal native adapter with `cargo build -p excalibur-sandbox --bin excalibur-network-bridge` before isolated network tests. Run `cargo test -p excalibur-sandbox -p excalibur-security -p excalibur-vault`, `cargo test -p excalibur-tools --test sandbox --test sandbox_adversarial --test protected_paths --test file_authority` and `cargo test -p excalibur-context --test trust`. Full workspace tests build the adapter through integration fixtures. `cargo test -p excalibur-engine --test out_of_band_approval` and security finalization tests exercise background approval ordering. Linux tests use verified bubblewrap, real C/Rust builds and isolated local HTTP/TLS/SOCKS fixtures; unavailable confinement fails closed. See [security contracts and limits](docs/development/security.md).

- Noninteractive verification: `cargo test -p excalibur-cli -p excalibur-eval -p excalibur-telemetry -p excalibur-models` and `cargo test -p excalibur-engine --test event_projection` exercise CLI exit codes, denied approvals, isolated trial policy, incremental artifacts, replay, usage and resource accounting. See [Noninteractive execution and evaluation](docs/development/noninteractive.md); official offline reference validation is documented in [telemetry](docs/development/telemetry.md). Tests remain local and synthetic.

- Verifiable-work checks: `cargo test -p excalibur-tasks`, `cargo test -p excalibur-engine --test verifiable_work` and `cargo test -p excalibur-eval --test verifiable` cover atomic planning, evidence freshness, completion, loops, child budgets and scoped integration. See [Verifiable work](docs/development/verifiable-work.md). All model verification fixtures are deterministic and local.

- Context/cache checks: `cargo test -p excalibur-context`, `cargo test -p excalibur-models --test cache`, `cargo test -p excalibur-journal --test context_instructions`, `cargo test -p excalibur-engine --test context_compaction --test context_session_races` and `cargo test -p excalibur-telemetry --test context_summary` verify literal instructions, scoped history, cache controls, calibration and real interruption during context preparation. See [Context and cache](docs/development/context-cache.md).

- Project-tool verification: `cargo test -p excalibur-workspace -p excalibur-code-intelligence`, `cargo test -p excalibur-tools --test tool_retrieval --test terminal_vs_tools --test project_tools --test project_monitor` and `cargo test -p excalibur-models --test deferred --test replay` cover retrieval, native deferred calls, confined LSP, incremental graphs, OS/durable leases, isolated integration and reversible snapshots. See [Project tools and editing concurrency](docs/development/project-tools.md).

- Browser environment verification: `cargo test -p excalibur-webd --test preflight` covers local configuration, disk admission, private directory ownership/modes, bounded Chrome version probing with descendant cleanup and process identity checks. Run it under both `umask 0077` and `umask 0022`; fixtures set cross-user file modes explicitly. `cargo build -p excalibur-webd` followed by `target/debug/excalibur-webd --preflight /absolute/path/web.toml` emits the actual environment report; provision the dedicated user and directories first. See [Browser environment](docs/development/browser.md). These checks do not provide application sessions or web tools.

- Chrome instance and CDP verification: `cargo test -p excalibur-cdp -p excalibur-browser` covers framing, correlation, cancellation, message limits, flags, process identities, renderer sandbox checks and version policy. `cargo test -p excalibur-browser --test cdp_contract -- --nocapture` requires real installed Chrome and a dedicated unprivileged user; it uses a local synthetic proxy, verifies every catalog command, OOPIF, 70 MiB isolation, 10,000 console events without a false instance crash, lifecycle backpressure reconciliation, crashes and two-instance parent death. Evidence lives in `target/test-evidence/browser/cdp_contract/`. Missing Chrome or confinement fails closed; only explicit `EXCALIBUR_BROWSER_TESTS=skip` skips real Chrome and must be reported. `target/debug/excalibur-webd --check-instance /absolute/path/web.toml` runs a temporary instance diagnostic with a deny-all local proxy, not a service. See [Browser environment](docs/development/browser.md).

- Browser session/service verification: `cargo test -p excalibur-browser --test sessions -- --nocapture` and `cargo test -p excalibur-webd --test webd_boundary -- --nocapture` exercise durable profiles, isolated contexts, tab ownership/limits/leases, listener recovery, JSON-RPC, peer credentials, operation reconciliation and real service restart/parent death. The default listener fixture runs for 600 seconds with local long-polling; `EXCALIBUR_LISTEN_TEST_SECONDS` only shortens development checks. Evidence is in `target/test-evidence/browser/{sessions,webd_boundary}/`. `excalibur-webd --serve /absolute/path/web.toml` runs the local protocol with a deny-all proxy pending broker integration; it does not install a service or register agent tools.

- Listener reconciliation verification: `cargo test -p excalibur-browser --test sessions listener_events_and_document_recovery -- --nocapture` uses real Chrome with local pages to check coalesced bursts, current unread counts, login/network unblock transitions for shared owners and target cleanup when a listener crashes on a login origin. Evidence is in `target/test-evidence/browser/listener_reconciliation/`. The unit lifecycle checks also ensure URL reconciliation does not clear security/version blocks or human control.
